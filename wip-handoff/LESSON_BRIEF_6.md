## Smoke environment and pitfalls (learned from real CI runs; follow all of them)
- Runner: GitHub `ubuntu-latest`, passwordless sudo, Docker 28 (runc), OpenTofu (`tofu`, no wrapper), Python 3.12, Node 22, a single-node kind cluster whose kubectl context is `kind-cc-smoke` (node container `cc-smoke-control-plane`). Every lesson's smoke runs one after another against that same cluster, so: use your own namespace (`cc-<lesson-slug>`), create it at the start, delete it in the EXIT trap, and undo anything cluster-wide you change (taints, labels, CRDs, ClusterRoles, webhooks). Pass `--context kind-cc-smoke` or check the current context first. Do not delete or recreate the cluster.
- Tools that are not preinstalled (helm, conftest/opa, pulumi, crossplane CLI, ansible-core): download the pinned version from `curriculum/versions.json` into `$WORK/bin` (official release URL; verify the published sha256 when the project publishes one) or `pip install` into a venv under `$WORK`. Never `curl | sh`.
- `set -euo pipefail` is on: `cmd | head`, `cmd | tee f | head` and `grep -q` on a long pipe can die with SIGPIPE (exit 141). Write to a file, then `head` the file.
- Never compare JSON as strings (spacing differs between Python's json.dumps and kubectl/docker); parse both sides.
- Error wording differs across versions: match stable tokens (`Errno 24`, `409`, `Forbidden`, `NotFound`), not whole sentences. Docker 28 says `network X not found`, not `No such network`.
- Alpine images use busybox and musl: `wget localhost` can try `::1` first while the server listens on IPv4 only (use `127.0.0.1`); musl words errno messages differently from glibc.
- `kubectl run -i --rm` loses output when the container exits before kubectl attaches. Create the pod, `kubectl wait --for=jsonpath='{.status.phase}'=Succeeded`, then `kubectl logs`, then delete.
- Waiting: always `kubectl wait`/`rollout status` with an explicit `--timeout`, never bare `sleep`. Image pulls on the runner take seconds to a minute; pin image tags (`python:3.12-alpine`, `alpine:3.22`, `registry.k8s.io/pause:3.10`, `nginx:1.29-alpine` etc.).
- The root `.gitignore` ignores `*.log`; fixtures named `*.log` under `code/fixtures/` are exempt, anything else ending in `.log` will not be committed.
- `kubectl get -o json` omits `metadata.managedFields` unless you pass `--show-managed-fields`.
- `kubectl wait --for=condition=...` fails at once, instead of waiting, on an object whose `status.conditions` does not exist yet (a CRD or a resource created a moment ago). Poll with `kubectl get -o jsonpath` in a loop with a deadline instead.
- Release checksum files do not always cover every asset (Argo Rollouts' omits `install.yaml`). Read the checksum file before you rely on it; pin a sha256 you computed yourself for assets it does not list, and say so in a comment.
- Kernel and tool versions change error codes and wording (newer kernels answer an rp_filter refusal with EINVAL, not EXDEV). Where a comparison depends on version-specific wording, accept both forms and print which one you saw.
- On Linux, libpcap delivers packets in blocks; anything that stops a capture right after generating traffic needs `tcpdump --immediate-mode` and a final marker packet it waits for.
- Images: `nginx:1.30-alpine` is the current stable nginx (1.29 stopped receiving updates). Confirm every other tag exists before you pin it.
- You will not be allowed to execute binaries you download on this Mac. Write the smoke so that its first real run in CI can succeed: read the tool's source or documentation for flags and output formats, make comparisons tolerant of formatting (parse, never diff text), and make every failure message print what it saw.

# Lesson specs

## git/object-store  (folder 03-git/01-object-store)  Build · python · 90 min
Title: "Git Is a Content-Addressed Object Store". Prereqs: linux/filesystem-mounts.
Build It: `minigit`. Loose objects (`blob`, `tree`, `commit`, `tag`) with their headers, zlib compression and SHA-1 IDs (and a note on the SHA-256 object format); tree entries with modes (100644, 100755, 120000, 040000, 160000) sorted the way Git sorts them; `hash-object`, `cat-file -t/-s/-p`, `write-tree` from a directory, `commit-tree` with author, committer, timestamps and time zones, refs and symbolic refs (`HEAD`), a reflog, `log` walking first parents, `checkout` of a tree into a directory, and an `fsck` that checks every reachable object hashes to its name. `--json`.
Use It: Git's plumbing: `git hash-object -w`, `git cat-file -p`, `git ls-tree`, `git write-tree`, `git commit-tree`, `git update-ref`, `git rev-parse`, `git count-objects -v`, `git fsck`, and what `.git/objects`, `.git/refs` and `.git/HEAD` hold.
Smoke: create a repository with minigit only (files, an executable, a symlink, nested directories, three commits) and assert `git fsck --strict` is clean, `git log` shows the commits with the right authors and dates, and `git cat-file` returns byte-identical content; create a repository with Git and assert minigit reads every object and computes the same IDs for the same content; hash a tree with an empty directory and a file named like a directory to show the sorting rule.
Outputs: `skill-git-plumbing-recovery.md`, `prompt-explain-git-object.md`.

## git/merge-algorithms  (folder 03-git/02-merge-algorithms)  Build · python · 90 min
Title: "A Merge Is a Three-Way Diff Against a Common Ancestor". Prereqs: git/object-store.
Build It: `minimerge`. Myers' O(ND) diff and the patience or histogram variant, unified diff output with context and hunk headers that `patch` accepts, merge-base as the best common ancestor in a commit graph (including criss-cross histories with several bases), a three-way line merge with conflict markers in merge and diff3 style, the cases where both sides made the same change, and a summary of what a recursive or ORT merge adds (virtual merge bases, rename detection) with a small rename detector by content similarity.
Use It: `git diff --diff-algorithm=myers|patience|histogram`, `git merge-base --all`, `git merge-file -p --diff3`, `git merge -s ort`, `git rerere`, conflict resolution workflows and why line-based merges get JSON and lockfiles wrong.
Smoke: on a corpus of generated file pairs, assert minimerge's diff applies with `patch` and produces the same added and removed lines as `git diff --no-index` with the same algorithm (compare the sets of changed lines, not the hunk text); build histories with Git (including a criss-cross) and assert minimerge's merge bases equal `git merge-base --all`; assert three-way merges of a table of cases produce the same result or the same conflict regions as `git merge-file`.
Outputs: `skill-merge-conflict-resolution.md`, `prompt-explain-merge-conflict.md`.

## git/packfiles-transport  (folder 03-git/03-packfiles-transport)  Build · python · 120 min
Title: "Cloning Is a Negotiation Plus a Packfile". Prereqs: git/object-store, networking/http-server.
Build It: `minipack`. The packfile format (header, per-object type and size varint, zlib streams, `OFS_DELTA` and `REF_DELTA` with copy and insert instructions, trailing checksum), the `.idx` version 2 index (fanout table, sorted IDs, CRC32, offsets), a delta encoder for similar blobs, and a client for Git's smart HTTP protocol v2: pkt-line framing, capability advertisement, `ls-refs`, and `fetch` with `want`, `have`, `done`, shallow `deepen` and a `filter blob:none`; unpack into a repository the object-store lesson can read.
Use It: `GIT_TRACE_PACKET=1 git clone`, `git clone --depth 1`, `--filter=blob:none` (partial clone) and `git sparse-checkout`, `git verify-pack -v`, `git index-pack`, `git gc` and why a repository with large binaries needs Git LFS.
Smoke: serve a repository with `git http-backend` behind a local CGI wrapper; clone it with minipack (full, shallow, and blob-less) and assert the object sets equal those of `git clone` with the same options (compare `git rev-list --objects --all` output); write a pack with minipack and assert `git index-pack` and `git verify-pack` accept it and that minipack's `.idx` is byte-identical to the one Git computes; assert the pkt-line exchange minipack logs matches the request structure in `GIT_TRACE_PACKET` output.
Outputs: `skill-large-repo-tuning.md`, `prompt-explain-git-trace-packet.md`.

## git/merge-queue  (folder 03-git/04-merge-queue)  Build · python · 75 min
Title: "Trunk-Based Development Is a Queue of Short Branches". Prereqs: git/merge-algorithms.
Build It: `mergequeue`. A model of how a team lands changes: branch protection as data (required checks, required reviews, CODEOWNERS approval, linear history, signed commits), a CODEOWNERS parser with gitignore-style patterns where the last match wins, a merge queue that tests the combination of queued pull requests speculatively, ejects a failing one and retests the rest, and batching; a simulator that shows how branch lifetime and team size drive conflict rate and queue wait, comparing long-lived feature branches with trunk-based development and feature flags. Driven against real local Git repositories.
Use It: GitHub rulesets and branch protection, the GitHub merge queue (`merge_group` event in workflows), CODEOWNERS syntax, stacked pull requests with `git rebase --update-refs`, GitLab merge trains.
Smoke: create a local repository and a set of branches that conflict in planned ways; run the queue with real `git merge` and a scripted check, and assert the final main equals the result of merging the passing branches in order, the conflicting or failing ones were ejected, and history is linear when required; check CODEOWNERS matching on a table of paths against the semantics of `git check-ignore` for the pattern subset they share, and print where CODEOWNERS differs from `.gitignore`.
Outputs: `skill-branch-protection-review.md`, `prompt-design-merge-strategy.md`.

## git/git-hooks  (folder 03-git/05-git-hooks)  Build · python · 75 min
Title: "Hooks Are Programs Git Runs at the Right Moment". Prereqs: git/object-store.
