## Smoke environment and pitfalls (learned from real CI runs; follow all of them)
- Runner: GitHub `ubuntu-latest`, passwordless sudo, Docker 28 (runc), OpenTofu (`tofu`, no wrapper), Python 3.12, Node 22, a single-node kind cluster whose kubectl context is `kind-cc-smoke` (node container `cc-smoke-control-plane`). Every lesson's smoke runs one after another against that same cluster, so: use your own namespace (`cc-<lesson-slug>`), create it at the start, delete it in the EXIT trap, and undo anything cluster-wide you change (taints, labels, CRDs, ClusterRoles, webhooks). Pass `--context kind-cc-smoke` or check the current context first. Do not delete or recreate the cluster.
- Tools that are not preinstalled (helm, conftest/opa, pulumi, crossplane CLI, ansible-core): download the pinned version from `curriculum/versions.json` into `$WORK/bin` (official release URL; verify the published sha256 when the project publishes one) or `pip install` into a venv under `$WORK`. Never `curl | sh`.
- `set -euo pipefail` is on: `cmd | head`, `cmd | tee f | head` and `grep -q` on a long pipe can die with SIGPIPE (exit 141). Write to a file, then `head` the file.
- Never compare JSON as strings (spacing differs between Python's json.dumps and kubectl/docker); parse both sides.
- Error wording differs across versions: match stable tokens (`Errno 24`, `409`, `Forbidden`, `NotFound`), not whole sentences. Docker 28 says `network X not found`, not `No such network`.
- Alpine images use busybox and musl: `wget localhost` can try `::1` first while the server listens on IPv4 only (use `127.0.0.1`); musl words errno messages differently from glibc.
- `kubectl run -i --rm` loses output when the container exits before kubectl attaches. Create the pod, `kubectl wait --for=jsonpath='{.status.phase}'=Succeeded`, then `kubectl logs`, then delete.
- Waiting: always `kubectl wait`/`rollout status` with an explicit `--timeout`, never bare `sleep`. Image pulls on the runner take seconds to a minute; pin image tags (`python:3.12-alpine`, `alpine:3.22`, `registry.k8s.io/pause:3.10`, `nginx:1.29-alpine` etc.).
- The root `.gitignore` ignores `*.log`; fixtures named `*.log` under `code/fixtures/` are exempt, anything else ending in `.log` will not be committed.
- `kubectl get -o json` omits `metadata.managedFields` unless you pass `--show-managed-fields`.
- `kubectl wait --for=condition=...` fails at once, instead of waiting, on an object whose `status.conditions` does not exist yet (a CRD or a resource created a moment ago). Poll with `kubectl get -o jsonpath` in a loop with a deadline instead.
- Release checksum files do not always cover every asset (Argo Rollouts' omits `install.yaml`). Read the checksum file before you rely on it; pin a sha256 you computed yourself for assets it does not list, and say so in a comment.
- Kernel and tool versions change error codes and wording (newer kernels answer an rp_filter refusal with EINVAL, not EXDEV). Where a comparison depends on version-specific wording, accept both forms and print which one you saw.
- On Linux, libpcap delivers packets in blocks; anything that stops a capture right after generating traffic needs `tcpdump --immediate-mode` and a final marker packet it waits for.
- Images: `nginx:1.30-alpine` is the current stable nginx (1.29 stopped receiving updates). Confirm every other tag exists before you pin it.
- You will not be allowed to execute binaries you download on this Mac. Write the smoke so that its first real run in CI can succeed: read the tool's source or documentation for flags and output formats, make comparisons tolerant of formatting (parse, never diff text), and make every failure message print what it saw.
- Keep each smoke under about 3 minutes. Print `▸` lines so a failure in CI is easy to locate, and include the failing output in every `fail` message.
- If your smoke installs something heavy (a controller, CRDs), wait for it with a timeout and clean it up in the trap.

## Security lessons (phase 11)
- Cryptography follows the batch rule: standard library only (`hashlib`, `hmac`, `secrets`, big-integer `pow()`), written from the specification and checked against published test vectors. Python's standard library has no AES; if your design needs authenticated encryption, implement ChaCha20-Poly1305 from RFC 8439 and test it on the RFC's vectors. Never invent a cipher.
- Never commit anything that looks like a real credential. Test tokens that match a provider's format (AWS access keys, GitHub tokens, Slack tokens, private keys) are generated at run time inside tests and smoke, never stored in the repository; the only literal allowed is AWS's documented example `AKIAIOSFODNN7EXAMPLE`. GitHub's secret scanning runs on this repository.
- Kubernetes security lessons run on the shared kind cluster: use your own namespace, label anything cluster-wide you create (webhook configurations, ValidatingAdmissionPolicies, ClusterRoles, CRDs) and delete it in the trap. A broken admission webhook blocks every later lesson's smoke: always set `failurePolicy: Ignore` or scope it with a `namespaceSelector` to your namespace only, and delete it even if the smoke fails.
- Security tools that are single binaries (gitleaks, trivy, grype, kube-bench, kyverno CLI, spire) follow the CI/CD rule: pinned release, checksum verified from the project's own checksum file, confirmed via the GitHub releases API. Falco runs as its pinned container image.

## observability/metrics-tsdb  (folder 10-observability/01-metrics-tsdb)  Build · python · 90 min
Title: "A Metric Is a Name, Labels and a Number Over Time". Prereqs: linux/performance-basics, networking/http-server.
Build It: `minitsdb`. A parser for the Prometheus text exposition format and OpenMetrics (HELP, TYPE, counters, gauges, histograms with `_bucket{le=}`, `_sum`, `_count`, summaries, exemplars ignored but parsed, escaping); a scraper with a target list, `scrape_interval`, `scrape_timeout`, the `up` and `scrape_duration_seconds` series, honour_labels, relabelling (keep, drop, replace, labelmap) and staleness markers when a series disappears; an in-memory TSDB with an append-only write-ahead log and chunks compressed with delta-of-delta timestamps and XOR-encoded floats (the Gorilla scheme Prometheus uses), retention, and a cardinality report (series per metric, label values per label, the worst offenders). `--json`.
Use It: Prometheus at the tracked version in Docker: `prometheus.yml` with `scrape_configs` and `relabel_configs`, the `/metrics` of a test app, `/api/v1/targets`, `/api/v1/series`, `promtool check metrics`, `promtool tsdb analyze` for cardinality, `node_exporter` for host metrics; why a `user_id` label is an outage.
Smoke: run a small test app exposing known counters, gauges and a histogram, scrape it with minitsdb and with Prometheus (pinned image) for the same window; assert the same series set (names and label sets, parsed from `/api/v1/series`), counter values that agree within one scrape, `up` dropping to 0 for a dead target in both, relabelling that drops the same series, a staleness marker after a series disappears, and a cardinality report whose top metrics match `promtool tsdb analyze` (run against the Prometheus data directory).
Outputs: `skill-cardinality-review.md`, `prompt-explain-metric-type.md`.

## observability/promql  (folder 10-observability/02-promql)  Build · python · 90 min
Title: "PromQL Is Vector Arithmetic Over Time Windows". Prereqs: observability/metrics-tsdb.
Build It: `miniql`. A PromQL subset evaluator over a series store loaded from OpenMetrics: instant and range vector selectors with label matchers (`=`, `!=`, `=~`, `!~`), the lookback delta, `offset` and `@`; `rate`, `irate`, `increase` with counter-reset handling and Prometheus's extrapolation rules, `avg_over_time`, `max_over_time`, `quantile_over_time`; aggregation with `by`/`without` (`sum`, `avg`, `max`, `count`, `topk`); binary operators with vector matching (`on`, `ignoring`, `group_left`, `group_right`) and comparison filters with `bool`; `histogram_quantile` over classic buckets; range queries with a step; an `explain` mode that shows which samples each output value used.
Use It: the Prometheus query API (`/api/v1/query`, `/api/v1/query_range`), the expression browser, recording rules, `promtool test rules` with input series, and the classic mistakes (`rate` of a gauge, `sum` before `rate`, a range shorter than two scrapes).
Smoke: generate deterministic OpenMetrics data (counters with a reset, a histogram, several label sets), backfill it into Prometheus with `promtool tsdb create-blocks-from openmetrics` (pinned image), and load the same file into miniql; run a table of 25 or more queries through both at fixed evaluation times and assert values agree within floating-point tolerance (parse the API JSON), including extrapolated `rate`, `increase` across the reset, `histogram_quantile`, and a `group_left` join.
Outputs: `skill-promql-review.md`, `prompt-explain-promql.md`.
