## Smoke environment and pitfalls (learned from real CI runs; follow all of them)
- Runner: GitHub `ubuntu-latest`, passwordless sudo, Docker 28 (runc), OpenTofu (`tofu`, no wrapper), Python 3.12, Node 22, a single-node kind cluster whose kubectl context is `kind-cc-smoke` (node container `cc-smoke-control-plane`). Every lesson's smoke runs one after another against that same cluster, so: use your own namespace (`cc-<lesson-slug>`), create it at the start, delete it in the EXIT trap, and undo anything cluster-wide you change (taints, labels, CRDs, ClusterRoles, webhooks). Pass `--context kind-cc-smoke` or check the current context first. Do not delete or recreate the cluster.
- Tools that are not preinstalled (helm, conftest/opa, pulumi, crossplane CLI, ansible-core): download the pinned version from `curriculum/versions.json` into `$WORK/bin` (official release URL; verify the published sha256 when the project publishes one) or `pip install` into a venv under `$WORK`. Never `curl | sh`.
- `set -euo pipefail` is on: `cmd | head`, `cmd | tee f | head` and `grep -q` on a long pipe can die with SIGPIPE (exit 141). Write to a file, then `head` the file.
- Never compare JSON as strings (spacing differs between Python's json.dumps and kubectl/docker); parse both sides.
- Error wording differs across versions: match stable tokens (`Errno 24`, `409`, `Forbidden`, `NotFound`), not whole sentences. Docker 28 says `network X not found`, not `No such network`.
- Alpine images use busybox and musl: `wget localhost` can try `::1` first while the server listens on IPv4 only (use `127.0.0.1`); musl words errno messages differently from glibc.
- `kubectl run -i --rm` loses output when the container exits before kubectl attaches. Create the pod, `kubectl wait --for=jsonpath='{.status.phase}'=Succeeded`, then `kubectl logs`, then delete.
- Waiting: always `kubectl wait`/`rollout status` with an explicit `--timeout`, never bare `sleep`. Image pulls on the runner take seconds to a minute; pin image tags (`python:3.12-alpine`, `alpine:3.22`, `registry.k8s.io/pause:3.10`, `nginx:1.29-alpine` etc.).
- The root `.gitignore` ignores `*.log`; fixtures named `*.log` under `code/fixtures/` are exempt, anything else ending in `.log` will not be committed.
- Keep each smoke under about 3 minutes. Print `▸` lines so a failure in CI is easy to locate, and include the failing output in every `fail` message.
- If your smoke installs something heavy (a controller, CRDs), wait for it with a timeout and clean it up in the trap.

## networking/ip-routing  (folder 02-networking/01-ip-routing)  Build · python, bash · 75 min
Title: "A Route Is a Longest-Prefix Match Plus a Rule Table". Prereqs: setup/lab-doctor.
Build It: `routelens`. CIDR arithmetic (IPv4 and IPv6: network, broadcast, containment, overlap, summarisation), parsing `ip -j addr`, `ip -j route show table all`, `ip -j rule` and `ip -j neigh`, and a from-scratch `ip route get`: policy rules in priority order (from, to, fwmark, iif, lookup table, blackhole/unreachable/prohibit), longest-prefix match within a table, metrics, scopes, preferred source address selection, ECMP next hops, and the reason when nothing matches; a neighbour check (FAILED/INCOMPLETE entries). `code/main.sh` builds the lab by hand. `--json`.
Use It: `ip addr`, `ip route`, `ip route get`, `ip rule`, `ip neigh`, `ip -j`, `traceroute`/`tracepath`, `/proc/sys/net/ipv4/ip_forward`, rp_filter, and how this maps to the VPC route tables you will meet in the Cloud phase.
Smoke: build three network namespaces (client, router, two upstreams) with veth pairs, addresses, a default route, a more specific route, a second table selected by `ip rule from`, and a blackhole route; export `ip -j` output from the client and router namespaces and assert routelens answers a matrix of destinations exactly as `ip route get` does (device, gateway, source, table), then confirm with `ping` from the namespace that the predicted path works and the blackhole fails.
Outputs: `skill-routing-triage.md`, `prompt-explain-ip-route-get.md`.

## networking/dns-resolver  (folder 02-networking/02-dns-resolver)  Build · python · 90 min
Title: "DNS Is a Recursive Walk Over UDP". Prereqs: networking/ip-routing.
Build It: `minidig`. The DNS wire format from RFC 1035 (header flags, question, resource records for A, AAAA, CNAME, NS, SOA, MX, TXT, SRV, name compression pointers both reading and writing), queries over UDP with a timeout and retry, TCP fallback when the TC bit is set, EDNS0 OPT records and buffer size, an iterative resolver that starts from configured root hints and follows referrals with glue, CNAME chasing with a loop limit, a TTL cache with negative caching from the SOA minimum (RFC 2308), and a `resolv.conf` parser that applies `search` and `ndots` to show every query a short name really sends. `--json`, `+trace`-style output.
Use It: `dig`, `dig +trace`, `dig +norecurse @server`, `dig +tcp`, `resolvectl query`, `getent hosts`, `/etc/resolv.conf` and `/etc/nsswitch.conf`, CoreDNS as an authoritative and forwarding server, why `ndots:5` makes Kubernetes pods send five queries for one name.
Smoke: run a pinned CoreDNS image with a small hierarchy you serve yourself (a fake root zone delegating `test.` to a second CoreDNS instance that delegates `cc.test.` to a third, with glue), resolve names with minidig iteratively from the fake root and with `dig +norecurse` step by step, and assert the same answers, TTLs and referral chain; check a truncated response falls back to TCP and an NXDOMAIN is negatively cached for the SOA minimum.
Outputs: `skill-dns-triage.md`, `prompt-explain-dig-output.md`.

## networking/tcp-states  (folder 02-networking/03-tcp-states)  Build · python · 90 min
Title: "Most Network Outages Are Timeouts You Did Not Set". Prereqs: networking/ip-routing, linux/file-descriptors.
Build It: `tcpwatch`. Parse `/proc/net/tcp` and `/proc/net/tcp6` (hex addresses, states, queues, timers, inode) and `ss -tanpi` output; the TCP state machine with a teaching simulator (three-way handshake, FIN and RST, TIME_WAIT and its 2MSL, CLOSE_WAIT as the application's bug); diagnoses for a socket table: CLOSE_WAIT build-up per process, SYN_RECV and listen-queue overflow (Recv-Q against the backlog), ephemeral port exhaustion against `ip_local_port_range`, retransmission timers; and a client library section that sets connect, read and total timeouts plus TCP keepalive (SO_KEEPALIVE, TCP_KEEPIDLE, TCP_KEEPINTVL, TCP_KEEPCNT where the platform has them) and shows what happens without them. `--json`.
Use It: `ss -tanpi`, `ss -lnt` (Recv-Q and Send-Q on a listener), `nstat` and `/proc/net/netstat` counters (ListenOverflows, TCPTimeouts), `sysctl net.ipv4.tcp_*`, `curl --connect-timeout --max-time`, and why a load balancer's idle timeout silently kills long-lived connections.
Smoke: start a Python server that accepts and never closes (CLOSE_WAIT leak), one with a tiny backlog that stops calling accept (listen overflow), and a client that connects to a blackholed address (connect timeout); assert tcpwatch's diagnoses match `ss` output and the `nstat` counters, and that the timeout client returns within the configured bound while the untimed one is still waiting.
Outputs: `skill-connection-timeout-triage.md`, `prompt-explain-ss-output.md`.

## networking/packet-capture  (folder 02-networking/04-packet-capture)  Build · python · 90 min
Title: "tcpdump Is a Filter Over Bytes You Can Parse". Prereqs: networking/tcp-states.
Build It: `pcaplens`. Read classic pcap files (global header, both byte orders, record headers, snaplen truncation) and the basic pcapng blocks (SHB, IDB, EPB); decode Ethernet, Linux cooked capture (SLL and SLL2, what `-i any` writes), IPv4, IPv6, TCP (flags, options such as MSS and window scale, SACK permitted) and UDP; a filter language subset compiled to Python predicates (`host`, `net`, `port`, `tcp`, `udp`, `and`/`or`/`not`, `tcp[tcpflags] & tcp-syn != 0`); per-connection stats by 4-tuple (handshake RTT, bytes each way, retransmissions, duplicate ACKs, zero windows, RSTs, who closed first); and DNS decoding of UDP/53 payloads. `--json`.
Use It: `tcpdump -i any -nn -s 0 -w file.pcap 'filter'`, `tcpdump -r -nn -tttt`, `tcpdump -d` to see the compiled BPF, rotating captures with `-C/-W`, capturing inside a pod's network namespace with `nsenter` or an ephemeral debug container, Wireshark and tshark as the next step.
Smoke: capture on loopback with `sudo tcpdump -i lo -w` while `curl` fetches from a local HTTP server, a client that sends an RST, and a `dig` against a local DNS server; assert pcaplens counts the same packets as `tcpdump -r` with the same filters, finds the handshake, the RST and the DNS question, and that a capture written with `-i any` (cooked header) decodes too.
Outputs: `skill-packet-capture-triage.md`, `prompt-explain-tcpdump-line.md`.

## networking/tls-handshake  (folder 02-networking/05-tls-handshake)  Build · python · 120 min
Title: "TLS Is a Handshake and a Chain You Can Verify". Prereqs: networking/tcp-states.
Build It: `tlslens`. Parse a TLS ClientHello and ServerHello from raw bytes (record layer, handshake header, versions, cipher suites, extensions: server_name, ALPN, supported_versions, key_share, signature_algorithms) captured by a small listener that records what a client sends; a DER/ASN.1 reader for X.509 certificates (subject, issuer, serial, validity, subjectAltName, basicConstraints, keyUsage, extendedKeyUsage, subject and authority key identifiers); chain building from a leaf through intermediates to a trust anchor; RSA signature verification (sha256WithRSAEncryption, PKCS#1 v1.5) with `pow()`, and ECDSA P-256 verification if you can do it cleanly; hostname matching with wildcards per RFC 6125; expiry and not-yet-valid checks; and an error report worded like OpenSSL's verify codes (unable to get local issuer, certificate has expired, hostname mismatch). `--json`.
Use It: `openssl s_client -connect -servername -showcerts -alpn`, `openssl x509 -noout -text`, `openssl verify -CAfile -untrusted`, `curl -v`, Python's `ssl` module, TLS 1.3 versus 1.2 handshakes, SNI-based routing, cert-manager and ACME as how certificates get issued and renewed.
Smoke: create a root CA, an intermediate and leaf certificates with `openssl` (one valid, one expired, one with the wrong SAN, one signed by an untrusted root), serve them with `openssl s_server` or Python's `ssl`, and assert tlslens's verdicts match `openssl verify` and `openssl s_client` for each case; capture a ClientHello from `openssl s_client` and from `curl` and assert tlslens reads the same SNI and ALPN values.
Outputs: `skill-tls-certificate-triage.md`, `prompt-explain-openssl-verify.md`.

## networking/http-server  (folder 02-networking/06-http-server)  Build · python · 90 min

Smoke: run minihttp and a pinned nginx container serving the same directory and proxying to the same upstream; send a matrix of requests (keep-alive reuse, range, conditional GET, chunked upload, a request with both length headers, a slow header sender, a slow upstream) and assert the status codes and the relevant headers match, parsing headers rather than comparing raw text.
Outputs: `skill-http-error-triage.md`, `prompt-explain-curl-verbose.md`.

## networking/load-balancing  (folder 02-networking/07-load-balancing)  Build · python · 90 min

Build It: `minilb`. ## networking/http-caching  (folder 02-networking/08-http-caching)  Build · python · 75 min
Title: "A Cache Is a Key, a Lifetime and a Validator". Prereqs: networking/http-server.
Build It: `minicache`.
